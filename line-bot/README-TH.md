# AirGuard LINE Bot — คู่มือเริ่มต้น

บอตนี้เป็นส่วนเพิ่มเติมของเว็บ AirGuard ใช้ LINE Messaging API ตอบข้อความในแชตส่วนตัว ผู้ใช้พิมพ์ `ฝุ่น หนองคาย`, `ฝุ่น กรุงเทพมหานคร`, `ฝุ่น กรุงเทพ`, `pm2.5 ขอนแก่น` หรือส่งตำแหน่งผ่าน LINE เพื่อรับค่าประมาณ PM2.5 ปัจจุบันจาก Open-Meteo พร้อมเวลาข้อมูลและคำแนะนำทั่วไป พิมพ์ `ช่วยเหลือ` เพื่อดูวิธีใช้ รองรับจังหวัดจากพิกัดตัวแทนในเว็บ (ควรตรวจสอบพิกัดก่อนใช้จริง)

## สิ่งที่ยังไม่ได้ทำ
นี่คือโค้ดบอตตอบเมื่อผู้ใช้ทักหรือส่งตำแหน่ง ยังไม่มีการแจ้งเตือนอัตโนมัติตามเวลา ระบบติดตามจังหวัด ฐานข้อมูล ระบบบัญชี LINE Login/LIFF หรือการเชื่อมบัญชีเว็บไซต์ โค้ดยังไม่ได้ deploy หรือทดสอบกับ OA จริง ต้องตั้งค่าและทดสอบก่อนเปิดใช้

## ขั้นที่ 1: สร้าง LINE Official Account
1. เข้าสู่ระบบด้วยบัญชี LINE ของคุณที่ https://manager.line.biz/ (หรือใช้ LINE OA ที่มีอยู่) และสร้างบัญชี AirGuard AI หากยังไม่มี
2. ในการตั้งค่าบัญชี OA เปิดการใช้ Messaging API และเลือกหรือสร้าง provider ตามขั้นตอนของ LINE แล้วไป https://developers.line.biz/console/ เพื่อเปิด Messaging API channel ของบัญชีนั้น
3. ใน LINE Developers Console ดู `Channel secret` จาก Basic settings และออก `Channel access token (long-lived)` ที่ Messaging API ตามคำแนะนำของ LINE เก็บสองค่านี้ไว้เฉพาะฝั่งเซิร์ฟเวอร์ ห้ามส่งแชต อัปโหลด GitHub หรือใส่ใน HTML/JavaScript หน้าเว็บ
4. หาก LINE ให้ลงทะเบียนข้อมูล Developer ในครั้งแรก ให้กรอกตามหน้าจอ ใช้บัญชี LINE เดิมได้ ไม่ต้องสมัคร LINE ส่วนตัวใหม่

เอกสารทางการ: https://developers.line.biz/en/docs/messaging-api/getting-started/

## ขั้นที่ 2: รันบนเครื่องเพื่อทดสอบ
ต้องมี Node.js รุ่น 18 ขึ้นไป ไม่ต้องลงแพ็กเกจเพิ่ม ตรวจเวอร์ชันด้วย `node --version` แล้วใน PowerShell (ทำบนเครื่องส่วนตัวเท่านั้น) ตั้งตัวแปรชั่วคราว:

```powershell
cd line-bot
$env:LINE_CHANNEL_SECRET = 'ใส่ Channel secret จริงของคุณ'
$env:LINE_CHANNEL_ACCESS_TOKEN = 'ใส่ Channel access token จริงของคุณ'
$env:PORT = '3000'
node bot.mjs
```

การทดสอบในเครื่องไม่ได้ทำให้ LINE จากอินเทอร์เน็ตเรียกเว็บฮุกได้เอง ห้ามแชร์ภาพหน้าจอหรือคำสั่งที่มีค่าจริง และอย่า commit ค่าความลับ เปิด `http://localhost:3000/health` ควรเห็น `{"ok":true}` แล้วทดสอบโค้ดด้วย `node --test bot.test.mjs`

## ขั้นที่ 3: ติดตั้งบนเซิร์ฟเวอร์ HTTPS
GitHub Pages เป็นเว็บแบบ static จึงรันบอตนี้ไม่ได้ ต้องใช้โฮสต์ Node.js ที่เปิดรับ HTTPS และอนุญาตขาออกไปยัง LINE และ Open-Meteo สร้างบริการจาก repository ระบุโฟลเดอร์ `line-bot` และคำสั่งเริ่ม `node bot.mjs` กำหนด environment variables `LINE_CHANNEL_SECRET` และ `LINE_CHANNEL_ACCESS_TOKEN` ในหน้า secret ของโฮสต์ ให้โฮสต์กำหนด `PORT` อัตโนมัติ อย่าใช้พื้นที่เก็บ source เก็บค่า secret

เมื่อ deploy แล้วจะได้ URL เช่น `https://example-host/webhook` (เป็นตัวอย่าง ให้ใช้ URL จริงจากโฮสต์ของคุณ) เปิด `https://example-host/health` เพื่อเช็กว่าเซิร์ฟเวอร์ทำงาน อย่าส่งค่าความลับไปใน URL

## ขั้นที่ 4: เชื่อม LINE
ใน LINE Developers Console → Messaging API → Webhook settings ใส่ URL HTTPS ที่ลงท้ายด้วย `/webhook` กด Verify และเปิด Use webhook จากนั้นเพิ่มเพื่อน OA ของคุณแล้วลองส่ง `ฝุ่น หนองคาย` และลองส่งตำแหน่ง หากตอบซ้ำตรวจข้อความตอบกลับอัตโนมัติและข้อความทักทายของ LINE Official Account Manager แล้วตั้งค่าให้เหมาะสม

หาก Verify ไม่ผ่าน: ตรวจว่า deploy สำเร็จ URL ถูกต้อง รวม `/webhook`, ตั้ง channel secret ของ channel เดียวกัน, HTTPS เปิดสาธารณะ และเซิร์ฟเวอร์ยังทำงาน ดู log ฝั่งโฮสต์โดยไม่เปิดเผย token

## ข้อมูลและข้อจำกัด
- ค่าฝุ่นและเวลาจาก Open-Meteo/CAMS เป็นค่าจากแบบจำลอง ไม่ใช่ค่าตรวจวัดสถานี Air4Thai ความละเอียดของแบบจำลองและเวลาที่อัปเดตอาจทำให้ค่าต่างจากพื้นที่จริง
- เซิร์ฟเวอร์ส่งพิกัดจังหวัดหรือพิกัดที่ผู้ใช้ส่งไปยัง Open-Meteo เพื่อขอข้อมูล ไม่มีฐานข้อมูลหรือการบันทึกตำแหน่งในโค้ดนี้ ผู้ให้บริการโฮสต์, LINE และ Open-Meteo อาจมีบันทึกของตนเอง ควรแจ้งผู้ใช้และจัดทำนโยบายความเป็นส่วนตัวก่อนเปิดสาธารณะ
- ตอบเฉพาะแชตส่วนตัว ไม่ตอบในกลุ่ม คำแนะนำไม่ใช่การวินิจฉัยโรค
- การส่งข้อความมีโควตาและเงื่อนไขของ LINE OA และบริการ Open-Meteo ให้ตรวจสอบก่อนเปิดบริการ
- ก่อนเพิ่มแจ้งเตือนอัตโนมัติ ต้องมีการยินยอม/ยกเลิก, ฐานข้อมูล, ระบบตั้งเวลา, วิธีจัดการส่งซ้ำและตรวจสอบความล้มเหลว รวมทั้งสิทธิในการลบข้อมูล
